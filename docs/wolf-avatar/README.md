# wolf 人偶 — 制作与交付指南

走廊里那个会挥手的人偶，本体是一块 **2D 立牌**（不是 3D 模型）：
一张平面贴上一组序列帧，按 `1→9→1` 来回播放。

- 组件：`src/components/canvas/corridor/Avatar.jsx`
- 素材：`public/textures/corridor/avatar_anim/1.webp` ～ `9.webp`
- 播放：20 FPS，`TOTAL_FRAMES = 9`，来回播（ping-pong）

---

## 一、作者原版的规格（实测数据）

从上游仓库 `ITomPoland/portfolio-itom` 拉下 9 张原图量出来的：

| 项目 | 值 |
|------|-----|
| 数量 | 9 张（`1.webp` ～ `9.webp`） |
| 尺寸 | **1024 × 1024** |
| 格式 | **WebP，带透明通道** |
| 体积 | 每张 42–45 KB |
| 内容高度 | 占画布 **100%**（上下顶满，y 0~1023） |
| 左边缘 | **恒定在 x=387**（9 帧完全不动） |
| 右边缘 | **879 → 728** 逐帧回收（挥手的手臂） |
| 九帧差异 | 第 1 帧 vs 第 5 帧有 **49%** 像素不同（真动画） |
| 留白 | 左 387、右 144、上 0、下 0 |

**作者的构图规律**：身体锚定在画面左侧一动不动，抬起的手臂朝右边伸出去，
再一帧一帧收回来 —— 正好对应 `1→9→1` 的来回播放。

## 二、要准备什么

### 素材

- **人物设定**：长什么样、什么颜色、穿什么。作者画的是米白毛 + 紫色兜帽的狼。
- **参考线模板**：本目录下的 `template-guides.png`
  （1024×1024，标出了身体锚点 x=387、手臂最远 x=879、动作区、满高范围）
  把它垫在最底层描着画，位置就不会跑偏。

### 工具（任选，能导出透明 PNG 序列就行）

| 工具 | 适合 | 备注 |
|------|------|------|
| Procreate（iPad） | 手绘 | 动画辅助功能可直接导出 PNG 序列 |
| Photoshop | 手绘 / 变形 | 时间轴做帧动画，导出「渲染视频 → PNG 序列」 |
| Krita（免费） | 手绘 | 有洋葱皮，适合逐帧 |
| Clip Studio Paint | 手绘 | 动画功能完整 |
| After Effects / Spine | 只画一张再变形 | 用骨骼或木偶变形摆出 9 个姿势，批量导出 |
| Blender | 3D 建模后渲染 | 渲成 2D 序列当然也行，但没必要 |

## 三、怎么做（两种路线）

### 路线 A：老老实实画 9 张（作者的做法）

1. 打开 `template-guides.png` 作为底层参考（导出前记得隐藏它）
2. **先把身体画完**（头、躯干、腿、另一只手），这部分 9 帧完全一致
3. 复制 9 个图层，**只改挥动的那只手臂**：
   - 第 1 帧：手抬到最高/最远（右边缘约 879）
   - 第 5 帧：手在中间
   - 第 9 帧：手收到最靠身体（右边缘约 728）
4. 其余 6 帧按这个摆动轨迹补中间的姿势
5. 逐帧导出 PNG，**画布锁定 1024×1024，透明背景**

> 关键：**除了手臂，别动任何像素**。身体一丝一毫的位移都会让立牌抖。

### 路线 B：只画一张，靠变形导出（省事）

1. 画一张「手抬到最远」的定稿（姿态对应第 1 帧）
2. 用工具的变形/骨骼功能，只对**手臂**做旋转：
   - PS 木偶变形（Puppet Warp）/ Krita 变形工具 / AE 木偶工具 / Spine 骨骼
3. 按摆动角度导 9 个姿势，**导出时不要自动裁切画布**
4. 需要注意：变形会让线条粗细略有变化，手绘风一般能接受

### 路线 C：只给一张，动画交给我

不想做 9 张也行 —— 给一张定稿，我在代码里加一个「呼吸 + 轻微摇摆」的待机动画
（缩放和旋转插值），比 9 张手绘省事，效果也不呆板。

## 四、导出设置（最容易踩的坑）

| 设置 | 要求 |
|------|------|
| 画布尺寸 | **锁定 1024 × 1024**，每一帧都必须一致 |
| 自动裁切 / Trim | **必须关掉**。开了之后每帧会按内容裁边，尺寸不一致 → 播放时人物乱跳 |
| 背景 | **透明**。实底贴进 3D 场景会显示成一块方块 |
| 格式 | PNG（无损、保留透明）最好，我会统一转 WebP 压体积 |
| 命名 | 无所谓，按文件名数字顺序排就行；不确定顺序就 `01.png`～`09.png` |
| 帧数 | 不必是 9。5 张、12 张、20 张都行，我改 `TOTAL_FRAMES` 即可 |

## 五、交付前自检

导出后跑一下这个脚本，它会替你检查尺寸、透明、内容范围、身体是否固定、帧之间有没有真差异：

```bash
cd portfolio-itom
node scripts/check-avatar-frames.mjs <你的帧文件夹>
```

输出示例：

```
=== 结论 ===
  ✓ 所有帧尺寸一致：1024x1024
  ✓ 全部 9 帧都有透明通道
  ✓ 左边缘稳定（波动 0 px），身体没在晃
  ✓ 帧之间有实际差异，是真动画

没有致命问题，可以直接给我了。
```

它会明确报出问题，比如：

- `✗ 每帧尺寸不一致` → 导出时开了自动裁切
- `✗ 这些帧没有透明通道` → 背景没设成透明
- `✗ 所有帧内容几乎完全相同` → 9 帧是同一张图，播起来不会动
